# 11. NORMALIZAÇÃO DA HIERARQUIA DO TEXTO PRÁTICO

O Markdown do Texto Prático possui hierarquia de `#`, `##` e `###` funcional para redação, mas ela NÃO deve ser copiada mecanicamente como hierarquia HTML.

Normalize editorialmente sem reordenar conteúdo.

Aplicar:

- abertura de seção → `section-opening`;
- Exemplo Resolvido → `<article class="resolved-example">`;
- Exercício → `<article class="exercise">`;
- Gabarito de exercício → `<article class="answer">`;
- título do exercício/exemplo → `h3.item-title`;
- subtítulos internos → `h4.minor-title` ou nível semanticamente correspondente;
- situações/cenas/objetos/composições internas → subtítulo local coerente;
- listas → `<ul>` / `<ol>`;
- tabelas → HTML tabular real;
- citações/enunciados destacados → `<blockquote>` quando semanticamente adequado.

Não criar uma nova taxonomia paralela de títulos.

---

# 12. ESTRUTURA DOS EXERCÍCIOS E EXEMPLOS

Exemplos longos e exercícios longos devem ser divisíveis por filhos.

Modelo:

```html
<article class="exercise"
         data-split="children"
         id="exercicio-05">

  <div class="keep-unit">
    <h3 class="item-title keep-with-next">
      Exercício 5 — A mesma postura, duas situações
    </h3>
    ...
  </div>

  ...
</article>
```

Regras:

- título + primeiro conteúdo devem permanecer juntos;
- não tornar exercício longo inteiro `atomic-group`;
- figuras + legendas devem permanecer indivisíveis;
- blocos curtos logicamente inseparáveis podem usar `keep-unit`;
- `data-split="children"` deve ser usado quando a unidade longa puder continuar entre páginas sem perda de sentido;
- não criar páginas quase vazias por excesso de atomicidade.
